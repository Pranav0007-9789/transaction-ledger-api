# Transaction Ledger API

A local backend API for accounts, credit/debit transactions, transaction history, and atomic transfers.

## Requirements
- Python 3.10 or newer
- Internet access for the first installation only

## Run on Windows

1. Install Python from https://www.python.org/downloads/ if it is not installed. During installation, tick **Add Python to PATH**.
2. Extract this ZIP file.
3. Open the extracted `transaction-ledger-api` folder.
4. Click the File Explorer address bar, type `cmd`, and press Enter.
5. Run:

   ```bash
   py -m venv .venv
   .venv\Scripts\activate
   python -m pip install -r requirements.txt
   uvicorn main:app --reload
   ```

6. Keep that terminal open.
7. Open http://127.0.0.1:8000/docs in your browser. This is the interactive API documentation.
8. SQLite creates `ledger.db` automatically in the project folder on first startup.

## Endpoints

| Method | Endpoint | Purpose |
|---|---|---|
| GET | `/` | Health check |
| POST | `/accounts` | Create an account (initial balance is always zero) |
| GET | `/accounts/{account_id}/balance` | Read current balance |
| POST | `/accounts/{account_id}/transactions` | Add credit/debit transaction |
| GET | `/accounts/{account_id}/transactions` | List history with filtering and pagination |
| POST | `/transfers` | Bonus: atomic transfer between accounts |

### Create account
`POST /accounts`

```json
{"name": "Pranav"}
```

The client cannot set the initial balance. The server generates the account ID and timestamp.

### Credit
`POST /accounts/{account_id}/transactions`

```json
{
  "type": "credit",
  "amount": 1000,
  "description": "Initial deposit",
  "reference_id": "deposit-001"
}
```

### Debit
```json
{
  "type": "debit",
  "amount": 300,
  "description": "Cash withdrawal",
  "reference_id": "withdrawal-001"
}
```

### Balance
`GET /accounts/{account_id}/balance`

### History
`GET /accounts/{account_id}/transactions?page=1&limit=10`

Filter by type:
- `GET /accounts/{account_id}/transactions?type=credit`
- `GET /accounts/{account_id}/transactions?type=debit`

Results are newest first. `page` must be at least 1 and `limit` must be between 1 and 100.

### Transfer (bonus)
`POST /transfers`

```json
{
  "source_account_id": "SOURCE_ACCOUNT_UUID",
  "destination_account_id": "DESTINATION_ACCOUNT_UUID",
  "amount": 50,
  "description": "Transfer",
  "reference_id": "transfer-001"
}
```

The API creates a debit and credit transaction and updates both balances in one database transaction.

## Error responses
The API returns meaningful HTTP errors, for example:
- `404`: account not found
- `409`: duplicate transaction reference
- `400`: insufficient balance
- `422`: invalid request, amount, type, or pagination

## Design and integrity
- Account and transaction IDs are generated by the server.
- Money is stored as integer paise/cents to avoid floating-point arithmetic in balance calculations.
- A database uniqueness constraint enforces `(account_id, reference_id)`.
- A write transaction makes inserting a transaction and updating the account balance atomic.
- There are no transaction update/delete endpoints, so transactions cannot be edited or deleted through this API.
- Foreign keys ensure transactions belong to existing accounts.

## Reset local test data
Stop the server with `Ctrl+C`, delete `ledger.db`, and start the server again. This permanently deletes local test data.

## Assumptions
1. Amounts are positive and may contain at most two decimal places.
2. Account names and descriptions must not be blank.
3. `reference_id` is unique per account, not globally.
4. The balance cannot go below zero.
5. Timestamps are generated by the server in UTC.
6. No authentication was requested in the assignment.
